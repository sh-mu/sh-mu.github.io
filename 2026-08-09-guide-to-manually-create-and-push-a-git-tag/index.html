Guide to manually create and push a Git tag

Here’s a quick, clear guide to manually create and push a Git tag.

  1. Create a Tag Locally
  2. Push the Tag to Remote
  3. Verify the Tag on Remote

Create Tag in GitHub

Tags in Git and GitHub are used to mark specific points in a repository’s history, often for version releases. You can create them either via the GitHub web interface or using Git commands locally.

Using Git Commands (Recommended for Flexibility)

For an annotated tag (recommended for releases with metadata):

git tag -a v1.0.0 -m "Release version 1.0.0"

For a lightweight tag (simple pointer to a commit):

git tag v1.0.0

Push the Tag to GitHub

Push a single tag or the specific tag to remote:

git push origin v1.0.0

Push all local tags: If you have multiple tags and want to push them all at once

git push origin --tags

This will upload every local tag that doesn’t exist on the remote. ⚠️ Not recommended if you have old or unwanted tags locally, as they will also be pushed.⚠️

Force Push an Updated Tag

If you’ve modified a tag (e.g., pointed it to a new commit), you must force push it:

git tag -f v1.0
git push -f origin v1.0

Use this with caution, as it overwrites the remote tag and may cause conflicts for others.

Verify Tags on Remote or on GitHub

After pushing, confirm the tags exist remotely:

git ls-remote --tags origin

Verify on GitHub

Go to your repository’s Tags section to confirm the tag is visible.

To list tags locally

git tag

Best Practices

  • Prefer annotated tags for public releases since they store metadata like author, date, and messages.

  • Use semantic versioning (e.g., v1.2.3) for clarity.

  • Avoid git push –tags unless you intend to share all local tags.

  • Remember that tags are not pushed automatically; you must explicitly push them.

  • Communicate with your team before force-pushing tags to prevent sync issues.

This ensures your tags are properly created, pushed, and visible both locally and on GitHub for collaboration and release tracking.
